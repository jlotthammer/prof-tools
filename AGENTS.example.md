# Explicit performance engineering

Invoke the installed `prof-tools` skill only when explicitly requested. That invocation also opts into Labcoat tracking for the campaign; do not require a separate Labcoat request or use Labcoat for unrelated coding work. Use the single CLI flow `diagnose` → `campaign start` → `evaluate` → `finalize`. Use `inspect` and the `prof_tools.*` Python modules only for advanced evidence inspection. Do not create additional `prof-tools` experiment tracking or decision state: install Labcoat separately and follow its canonical note, artifact and concurrency contracts.

The user supplies a natural-language optimization goal, not JSON or helper scripts. The agent owns creating and validating `perf/workload.json`, appropriate benchmark and correctness adapters, and the externally stored opportunity map. Read `skills/prof-tools/references/contract-authoring.md`; create an independent preparation clone and commit the workload contract and harness **there**, not in the source repository, before freezing the prepared base. Ask for missing scientific requirements only when evidence cannot establish them. Before modifying optimized code, establish the representative application objective, independent correctness tests, workload distribution and a frozen baseline. Screen all seven intervention families, then falsify hypotheses in worktrees backed by a **separate campaign Git repository**; commit notes in a separate Labcoat Git repository. Never add experiment branches or commits to the original source Git database. Verify correctness before benchmark acceptance; measure weighted end-to-end performance without a profiler. Memory is secondary unless capacity is binding.

After exploration, rebuild the retained ideas from the prepared base in an isolated integration worktree with one coherent API. Rerun evaluation on the exact final commit and dispatch an independent, read-only semantic architecture reviewer. Land only a reviewed consolidated patch in the source repository. Never push experiment refs. Keep external campaign Git history while Labcoat notes reference it. Never treat a microbenchmark win or a self-attested JSON PASS as a Labcoat KEEP decision.
