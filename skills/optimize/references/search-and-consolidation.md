# Branching search and final integration

Screen **algebra, dataflow, scheduling, memory, library, kernel, distributed** candidates before implementation. Require a mechanism, falsification test and representative workload opportunity estimate; when exposed time is unobserved, mark it unknown rather than inventing an Amdahl fraction. Memory is secondary unless capacity, paging or another explicit requirement is binding.

The agent authors and validates the opportunity specification from real baseline evidence (see [contract authoring](contract-authoring.md)), then invokes `prof-tools campaign start --repo <isolated-preparation-clone> --base <sha> --opportunities <generated-opportunity-path> --worktrees <new-campaign-directory> --labcoat-repo <persistent-external-notes-repository> --out ../campaign.json`. This is an internal artifact, not a user-provided file. This command validates the seven-family screen, selects diverse hypotheses, creates unique Labcoat-compatible experiment IDs and distinct Git worktrees inside a separate bare Git repository. The original source has **no experimental branches, objects, notes, or commits**. All experiment notes are committed to an independent Labcoat repository, linked into worker checkouts through ignored symlinks. Agents follow Labcoat's own preregistration, concurrent ownership, notes and experiment-decision rules. Do not infer a KEEP decision from a branch's local speedup. Backtrack on dead ends and revisit different intervention families; combine successful directions only under a new integration experiment.

For the final branch, **start from the prepared base inside the isolated campaign Git database**, do not merge exploratory scaffolding. Reimplement retained ideas using one clear interface/dataflow and remove temporary flags, parallel versions and abandoned configuration. The independent architecture reviewer evaluates ten dimensions: semantic preservation, conceptual economy, coherent API, ownership, necessity, simpler alternatives, scope discipline, no exploration residue, maintainable tests, and every file in the original-to-final diff. The candidate must be re-evaluated at the exact final commit before `prof-tools finalize`. Only after validation, export a reviewed final diff (rather than experimental commit history) into the original source repository. Do not delete the campaign Git database while Labcoat notes still reference its commits.
